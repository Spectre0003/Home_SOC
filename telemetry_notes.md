# Home SOC — Telemetry Notes

## 1. Purpose

This document records observations made while examining native endpoint telemetry in the Home SOC lab.

The goal is to understand the raw telemetry generated by the operating systems before introducing additional tools such as Sysmon or a SIEM.

The investigation workflow is:

```text
Generate Activity
       ↓
Endpoint Records Event
       ↓
Inspect Raw Telemetry
       ↓
Identify Relevant Fields
       ↓
Determine Detection Opportunities
```

# 2. Windows Security Event Logs

## 2.1 Event ID 4624 — Successful Logon

### Description

Event ID `4624` represents a successful account logon.

Microsoft documents 4624 as the event generated when a logon session is created on the destination computer.

Source:

- Log: `Security`
- Provider: `Microsoft-Windows-Security-Auditing`
- Event ID: `4624`
- Computer: `homesoc-windows`

---

### Observed Event

A successful login to the local Windows console generated:

```text
Event ID: 4624
Logon Type: 2
Target User: socadmin
Target Domain: HOMESOC-WINDOWS
Authentication Package: Negotiate
Logon Process: User32
Source IP: 127.0.0.1
Source Port: 0
```

### Important Fields

| Field | Observed Value | Meaning |
|---|---|---|
| Event ID | `4624` | Successful logon |
| TargetUserName | `socadmin` | Account that successfully logged in |
| TargetDomainName | `HOMESOC-WINDOWS` | Computer/domain associated with the account |
| LogonType | `2` | Interactive logon |
| LogonProcessName | `User32` | Windows interactive logon process |
| AuthenticationPackageName | `Negotiate` | Authentication package used |
| WorkstationName | `HOMESOC-WINDOWS` | Workstation associated with the event |
| IpAddress | `127.0.0.1` | Localhost; authentication originated locally |
| IpPort | `0` | No remote source port |
| ProcessName | `C:\Windows\System32\svchost.exe` | Process associated with the event |
| TargetLogonId | `0x28c1b0` | Identifier for the created logon session |

### Interpretation

The event represents a normal local interactive login.

The observed activity can be represented as:

```text
User
  ↓
Windows Login Screen
  ↓
Successful Authentication
  ↓
Event ID 4624
  ↓
Logon Type 2
  ↓
Source 127.0.0.1
```

The `127.0.0.1` source address is consistent with the authentication occurring locally on the Windows machine rather than from another SOC-LAB host.

## 2.2 Event ID 4625 — Failed Logon

### Description

Event ID `4625` represents a failed account logon.

Microsoft documents 4625 as a logon failure event generated on the computer where the logon attempt occurred.

Source:

- Log: `Security`
- Provider: `Microsoft-Windows-Security-Auditing`
- Event ID: `4625`
- Computer: `homesoc-windows`

---

### Observed Event

A failed login was deliberately generated by entering an incorrect password for the `socadmin` account.

The resulting event contained:

```text
Event ID: 4625
Target User: socadmin
Target Domain: HOMESOC-WINDOWS
Logon Type: 2
Status: 0xc000006d
SubStatus: 0xc000006a
Logon Process: User32
Authentication Package: Negotiate
Source IP: 127.0.0.1
Source Port: 0
```

### Important Fields

| Field | Observed Value | Meaning |
|---|---|---|
| Event ID | `4625` | Failed logon |
| TargetUserName | `socadmin` | Account targeted by the login attempt |
| TargetDomainName | `HOMESOC-WINDOWS` | Computer/domain associated with the account |
| LogonType | `2` | Interactive logon |
| Status | `0xc000006d` | General authentication/logon failure |
| SubStatus | `0xc000006a` | Incorrect password |
| LogonProcessName | `User32` | Windows interactive logon process |
| AuthenticationPackageName | `Negotiate` | Authentication package used |
| WorkstationName | `HOMESOC-WINDOWS` | Workstation associated with the event |
| IpAddress | `127.0.0.1` | Localhost |
| IpPort | `0` | No remote source port |
| ProcessName | `C:\Windows\System32\svchost.exe` | Process associated with the event |

### Interpretation

The event represents an unsuccessful local interactive authentication attempt.

The activity can be represented as:

```text
User
  ↓
Windows Login Screen
  ↓
Incorrect Password
  ↓
Authentication Failure
  ↓
Event ID 4625
  ↓
Status 0xc000006d
  ↓
SubStatus 0xc000006a
```

The `0xc000006a` substatus corresponds to a bad/incorrect password.

# 3. 4624 vs 4625

The two events were generated deliberately to establish a baseline for authentication telemetry.

| Field | 4624 | 4625 |
|---|---|---|
| Result | Success | Failure |
| Account | `socadmin` | `socadmin` |
| Logon Type | `2` | `2` |
| Logon Process | `User32` | `User32` |
| Authentication Package | `Negotiate` | `Negotiate` |
| Source IP | `127.0.0.1` | `127.0.0.1` |
| Status | N/A | `0xc000006d` |
| SubStatus | N/A | `0xc000006a` |

### Observation

Most contextual fields were identical because both events originated from the same Windows console.

The primary difference was the authentication result:

```text
4624 → Successful authentication

4625 → Failed authentication
```

This demonstrates why a SOC should examine multiple event fields rather than relying exclusively on the Event ID.

# 4. Detection Concepts

A basic detection could identify failed authentication attempts:

```text
IF EventID == 4625
THEN
    Authentication failure detected
```

However, a single failed login is not necessarily suspicious.

A user may simply enter an incorrect password.

A more useful detection would consider frequency and context.

For example:

```text
IF
    EventID == 4625
AND
    multiple failures occur
AND
    failures originate from the same source
WITHIN
    a short time window
THEN
    Potential brute-force activity
```

Example:

```text
4625
4625
4625
4625
4625
   ↓
Repeated authentication failures
   ↓
Potential brute-force activity
```

Additional context such as:

- Source IP
- Target account
- Logon type
- Failure status
- Time
- Number of attempts
- Whether the account is privileged

can be used to improve detection accuracy.

# 5. Analyst Questions

When investigating authentication events, the following questions should be considered:

```text
WHO?
    Which account was involved?

WHAT?
    Was the authentication successful or unsuccessful?

WHEN?
    When did the event occur?

WHERE?
    Which endpoint generated the event?

FROM WHERE?
    What was the source IP or workstation?

HOW?
    What logon type and authentication package were used?

HOW OFTEN?
    Is this a single event or part of a repeated pattern?

WHY?
    Is the activity expected or suspicious?

WHAT HAPPENED NEXT?
    Did the authentication lead to other activity?
```

# 6. Current Findings

The first Windows telemetry investigation established that:

- Windows records successful authentication as Event ID `4624`.
- Windows records failed authentication as Event ID `4625`.
- Logon Type `2` represents an interactive logon.
- The source address can provide context about where an authentication originated.
- Status and SubStatus fields provide additional information about authentication failures.
- Logon IDs can be used to correlate related activity.
- A single authentication event provides limited context; multiple events and telemetry sources are required for deeper investigation.
